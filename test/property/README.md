# FLAC decoder property test

This directory contains a deterministic malformed-input campaign and a
sample-exact differential test against ffmpeg.

## What is covered

- 200 malformed streams, 50 in each category:
  - truncation in metadata headers, metadata bodies, audio frames, and tail;
  - illegal metadata types, lengths, STREAMINFO fields, Vorbis comments,
    pictures, SEEKTABLEs, and CUESHEETs;
  - metadata blocks whose 24-bit declared length is `0xffffff` while the
    stream ends early, plus oversized STREAMINFO frame-size fields;
  - backward/wrapping SEEKTABLE offsets, duplicate/backward seek tables, and
    CUESHEET tracks whose offsets or track numbers move backwards.
- 50 valid streams generated by ffmpeg, covering 8-192 kHz, mono/stereo,
  16/24-bit, compression levels 0-8, and all FLAC stereo channel modes.
- For valid streams, every interleaved sample is compared exactly against
  ffmpeg's `pcm_s32le` decode. Any mismatch reports sample index, frame,
  channel, and byte offset.

Native FLAC metadata is a linear block chain, not an arbitrary object graph.
The "cycle" category therefore models the only file-relative back references
in the format: SEEKTABLE stream offsets and CUESHEET track offsets that point
backwards or wrap around. The stream decoder may tolerate semantically illegal
seek/cue metadata; the harness separately calls
`FLAC__metadata_object_seektable_is_legal()` and
`FLAC__metadata_object_cuesheet_is_legal()` and reports the result.

## Building with sanitizers

The campaign is intended to run one file per process so that a leak, crash, or
out-of-bounds report is attributable to exactly one input.

```sh
cmake -S . -B build-property -G Ninja \
  -DCMAKE_BUILD_TYPE=RelWithDebInfo \
  -DBUILD_TESTING=ON -DBUILD_PROGRAMS=OFF -DBUILD_EXAMPLES=OFF \
  -DBUILD_DOCS=OFF -DBUILD_CXXLIBS=OFF -DWITH_OGG=OFF \
  -DWITH_ASM=OFF -DWITH_AVX=OFF -DINSTALL_MANPAGES=OFF \
  -DCMAKE_C_FLAGS='-O1 -g -fno-omit-frame-pointer -fsanitize=address,undefined,leak -fno-sanitize-recover=all' \
  -DCMAKE_EXE_LINKER_FLAGS='-fsanitize=address,undefined,leak'
cmake --build build-property --target flac_property
ctest --test-dir build-property -R '^flac_property$' --output-on-failure -V
```

The resulting report is written under
`build-property/test/property/report/`.

## Standalone run

```sh
bash test/property/run_property_tests.sh \
  --binary build-property/test/property/flac_property \
  --work artifacts/flac-property/work \
  --report artifacts/flac-property/report \
  --ffmpeg ffmpeg --ffprobe ffprobe --python python3
```

Requirements: CMake, a C compiler, Python 3, ffmpeg, and ffprobe.

## Diagnosing failures

Each malformed file runs with a 15-second timeout. The runner classifies a
non-zero exit as `oob`, `leak`, `ub`, `crash`, `timeout`, `invariant`, or
`harness_failure`. The report records:

- `reported_offset`: byte offset from the start of the FLAC stream, taken from
  `FLAC__stream_decoder_get_decode_position()` at the first decoder error or
  from the sanitizer death callback;
- `injected_offset`: the offset where the corpus generator injected the
  malformation;
- whether the decoder rejected, recovered after errors, or accepted the stream;
- whether the metadata chain reader and semantic metadata validators accepted
  the metadata.

Representative counterexamples are copied to `report/counterexamples/`. When a
campaign has no failing case, the directory contains one representative
malformed file from each category, including accepted-but-semantically-illegal
cycle examples.
